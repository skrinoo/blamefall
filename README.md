# 锅从天降 · BlameFall

> **一款教你甩锅的爽游，和一堂教你接锅的课。**

60 秒一局。锅从天上掉下来，你得在落地前把它甩给某个人，并当场给出一个理由。

**双击 `index.html` 就能玩。** 零构建、零依赖、零安装，断网也能玩。

---

## 立即试玩

```
用浏览器打开 blamefall/index.html
```

没有 `npm install`，没有构建步骤，**离线也能完整玩**。
本项目全部用经典 `<script>` 而不是 ES module——因为 `file://` 协议下 module 会被 CORS 拦掉，
而这个游戏必须做到「下载下来双击就能跑」。

按 <kbd>`</kbd> 键可以呼出开发者面板，看每一次判定的 P / S / A / G 实算过程、文案来源，
以及这次判定走的是查表、AI 还是本地兜底引擎。

### 两种形态

| 形态 | 怎么跑 | 自由输入由谁判 |
|---|---|---|
| **离线** | 双击 `index.html`（`file://`） | 本地兜底引擎 |
| **在线** | 通过 http(s) 提供（部署态，或 `scripts/dev-server.ps1`） | 真 AI 裁判 `/api/judge` |

页面通过 http(s) 打开时会**自动**把 `apiBase` 指向自己的 origin，所以部署上去就是活的，
不需要任何人改配置；`file://` 下则保持离线。两种形态的玩家侧体验一致。
部署与环境变量见 **[`docs/DEPLOY.md`](docs/DEPLOY.md)**。

## 怎么玩

### 四个动词

| 动词 | 操作 | 代价 |
|---|---|---|
| **抓** | 点击空中的锅 | 时间减速到 0.3 倍，但有 **12 秒**真实时间的握持预算，超手就滑 |
| **甩** | 抓着锅点某个 NPC | 消耗一次甩锅机会，对方会疲劳 |
| **辩** | 选一种论证方式 | 快速选项查表（0ms），或自己打字（走 AI 判定） |
| **接** | 点自己 | **隐藏动词**。不得分，心理阴影 −8，接锅信用 +1 |

### 五种论证

```
事实型  援引客观事实、记录、已有分工        「这部分是他上周认领的」
情感型  援引自己的状态、付出、情绪          「我这几天真的已经尽力了」
转移型  援引流程、制度、职责边界            「这个环节本来就没人明确负责」
反向型  把对方的行为当作自己行为的原因      「是您让我这么做的」   ← 需接锅信用 ≥ 3 解锁
荒诞型  援引无法证伪的玄学、超自然前提      「水星逆行」
```

### 三幕节奏（60 秒）

| 幕 | 时间 | 名字 | 变化 |
|---|---|---|---|
| 第一幕 | 0-20s | **爽** | 锅掉得慢、接受度 +12，让你先爽起来 |
| 第二幕 | 20-45s | **紧** | 掉速加快、同时在空中的锅变 2 口，加成归零 |
| 第三幕 | 45-60s | **停** | 掉得最慢，但接受度 −6——所有人都累了 |

### 五种结局

成功 / 失败 / **被反甩** / **延期交付**（甩给未来的自己）/ **悬空**（辅导员既不接也不拒，把这件事按住了）

## 它到底在讲什么

这不是一个「甩锅越多分越高」的游戏。

**心理阴影面积**从 12 开局，上限 100，满了就崩溃、本局提前结束。
甩锅成功会加阴影，加多少取决于你甩给了谁：

- 甩给**学弟学妹**（`moralCost: 高`）—— 最好甩，得分最低，阴影 **+2**
- 甩给**天气 / 水逆 / 你的星座** —— 永远成功，永远只值 30 分，阴影 **0**
- 甩给**导师**（难度 3.0）—— 常规路径根本推不动，但得分最高

**接锅是全游戏唯一能降低阴影的手段。** 它不得分。

于是玩家会自己发现一件事：

> 得分最高的策略，和让你活到最后的策略，不是同一个。

游戏全程不说教。它只是把这两条曲线画在你面前，让数值自己讲话。
卷宗（结算页）会给出你的「甩锅体质报告」和一份数据驱动的「防甩锅手册」。

### 那个「漂亮的设计涌现」

判定公式是：

```
P = S × 0.4 + A × 0.4 + G × 0.2          P ≥ 0.6 → 甩锅成功

S  说服力 (0-100)   这个理由本身的论证质量
A  接受度 (0-100)   对方此刻愿不愿意接
G  锅归属 (0.0-1.0) 这口锅本来该不该他背
```

全库 1190 个组合跑下来，**P 值最高的那一次不是最好甩的，而是最有事实依据、
锅归属最清晰的那一次**（`trash → 室友 · 事实型`，P = 0.82）。

游戏在数值层面奖励「厘清责任」、惩罚「欺负老实人」，一句台词都没写。

## 架构：AI 不在热路径上

这是本项目最重要的一个决定。

快速选项的理由文本是**写死的**，所以它的判定结果可以在构建期一次性生成，运行时纯查表：

| | 调 AI | 查表 |
|---|---|---|
| 延迟 | ~800ms | **0ms** |
| 成本 | 每次约 130 tokens | **0** |
| 断网 | 不可玩 | **可玩** |

实测约 **90% 的操作走查表路径**。只有「自由输入」才真的调 `/api/judge`。

> **锅也可以由 AI 生成（热路径）**：接入 key 后，`/api/genpot` 会在后台预生成带
> `targetRole` 标注的新锅（连锅的类型、正文、五条理由一起生成），客户端 `engine/potgen.js`
> 把它们缓进缓冲；甩锅那一刻仍从缓冲 **0ms 取用**，AI 只在「需要之前」跑，铁律不破。
> 没接 key（`file://` 直开）就是冷路径，全用静态锅池。生成失败 / 超时 / 坏批一律静默落回静态锅。

```
data/verdicts.js    54 条判定库 + 每种论证类型 3 条通用兜底文案
engine/fallback.js  说服力 S 对固定文本实算（关键词表 + 长度 + 类型匹配 + 公文腔加成）
engine/judge.js     P 公式、完美论证暴击、五种结局
engine/api.js       只管自由输入；返回值只有「通过全字段校验的对象」或 null
engine/potgen.js    AI 锅预生成缓冲（热路径取用 / 冷路径兜底，与 genpot.mjs 同源校验）
api/genpot.mjs      GET/POST /api/genpot：让网关生成 n 口锅，服务端逐口洗成引擎可用的 def
api/probe.mjs       GET/POST /api/probe：拿玩家的 key+model 真调一句极简 prompt，回答「能不能用」
```

`api.js` 的契约是：**「有返回」不等于「可用」**。
超时 / 网络错 / 空响应 / JSON 坏 / 字段越界，一律返回 `null`，上层切本地兜底引擎，
玩家侧完全无感。超时的响应即使后到也**必须被丢弃**——否则会出现
「气泡已经显示兜底文案，半秒后又被 AI 文案覆盖」的闪烁。

### 一条被撞了四次才学会的铁律

> **凡是可以查表或可以用规则算出来的确定性游戏数据，一律不让 LLM 输出。**
>
> LLM 只负责三件事：理解自然语言论证的质量、为一种行为命名、写一句有洞察的点评。

四次失败的完整记录（`moral_cost` 漂移 → `argument_type` 漂移 → `pot_ownership` 错判 0.8
→ `power_success` 把荒诞型评成全场最强的 90-92 分）见 **[`docs/DEVLOG.md`](docs/DEVLOG.md) 第 3 节**。

### 自带 API Key 与选模型（可选）

标题屏有一块「AI 裁判 / 生成锅」设置区：**一个 AI 总开关** + 玩家可填自己的网关 Key 和模型 ID。
开关与 Key 的组合决定了「是不是 AI 版、token 记谁账上」：

| AI 开关 | Key | 实际版本 | token 记在 |
|---|---|---|---|
| 关 | 任意 / 留空 | 无 AI 判定 + 无 AI 生成锅（纯本地兜底 + 静态锅） | 不消耗任何 token |
| 开 | 留空 | 有 AI 判定 + AI 生成锅（作者兜底） | 作者网关账户 |
| 开 | 填了 | 有 AI 判定 + AI 生成锅（玩家凭据） | 玩家网关账户 |

> **作者兜底 AI 只在有后端的部署（Vercel）上生效**：GitHub Pages 是纯静态、没有 `/api`，那里无论开关如何都是无 AI 版（badge 会显示「该部署无后端」）。

开关存 `localStorage`（`bf.aiEnabled`）。关闭时 `isOnline()` 恒 false：judgeFree 直接 null、PotGen 不预取、
**不发任何 AI 网络请求**（浏览器实测 fetch 调用数 0）。

> **badge 说真话（本次修复的 bug）**：静态宿主（GitHub Pages）没有 `/api/*`，旧版只看「http 同源」就谎报
> 「热路径 · 作者兜底 Key」，而实际每个 AI 请求都 404、静默退化成无 AI 版。现在开机先 `GET /api/health`
> （**不带任何凭据**）探测后端真伪与作者有没有配 key，badge 据此显示真实状态
> （如「该部署无后端 · 本地兜底 + 静态锅」「后端在 · 无作者 Key（需自填）」）。

其余细节：

- **Key 记在自己账上**：填了之后，`/api/judge`、`/api/genpot`、`/api/probe` 的请求会带上
  `x-bf-key` / `x-bf-model` 头，服务端 `gatewayConfig(req)` 优先用请求级凭据，token 消耗记在玩家自己的网关账户；
  留空则回落服务端 `BLAMEFALL_API_KEY`（作者兜底）。**`base` 始终只认环境变量**——允许请求改 `base` 等于开放 SSRF，不做。
- **首次打开才提醒**：没存过 Key 时设置区高亮 + 一行提示；填过就存进 `localStorage`（`bf.apiKey` / `bf.model`），
  之后打开自动回填、不再打扰。只存玩家自己浏览器，不上报任何地方。
- **选模型 + 检测可用性**：「检测」按钮打一次 `/api/probe`，用当前 Key/模型真调一句极简 prompt。
  probe 的关键契约是**上游失败也返回 200**（`ok:false` + 错误码），因为「模型不可用 / Key 无效 / 余额不足」
  是要**展示给用户的正常结论**，不是服务错误。前端把错误码翻译成提醒（401 Key 无效、402 余额不足、404 模型不存在……）。

## 重新生成判定库（可选）

判定库已经落盘并且人工精修过，**不重新生成也完全能玩**。
如果你想用自己的 key 重跑一遍：

```powershell
# 1. 密钥只从环境变量读，脚本里不出现任何明文
$env:BLAMEFALL_API_BASE = 'https://your-gateway/v1'
$env:BLAMEFALL_API_KEY  = 'sk-...'

# 2. 先空跑，看会生成哪些组合、prompt 长什么样（不发起任何网络请求）
cd blamefall/scripts
.\generate-verdicts.ps1 -DryRun

# 3. 真跑
.\generate-verdicts.ps1

# 只重做某几个 NPC
.\generate-verdicts.ps1 -Only daoshi,ex -Force
```

产物是 `data/verdicts.generated.js` 和 `docs/generation-report.md`。
**它不会覆盖 `data/verdicts.js`**——那一份是人工精修的线上版本，两者并排存在，由人决定采纳哪些。

脚本会用字段名黑名单（`power|score|persuas|rate|prob|rating|weight`）拦下任何数值字段：
**模型只要敢打分，条目就被丢弃并记进失败报告。**

> 兼容 Windows PowerShell 5.1 与 PowerShell 7。
> `.ps1` 文件必须保存为 **UTF-8 with BOM**，否则 5.1 会按系统 ANSI 代码页读取，中文全成乱码。
> 另外两个编码坑（请求体必须传 UTF-8 字节、响应必须自己从 `RawContentStream` 解码）
> 已在代码里规避并注明「改动时请勿简化掉」。

## 自检

`game.js` 每次开局会跑 `selfTest()`：四条判定案例，期望值写死在代码里。

```
ppt      → 学弟学妹 · 事实型   S=70   expect P=0.70
ppt      → 导师     · 反向型   S=65   expect P=0.28    （前提：接锅信用 ≥ 3）
electric → 水逆     · 荒诞型   S=15   expect P=1       （抽象 NPC 跳过判定）
trash    → 室友     · 事实型   S=85   expect P=0.82
```

引擎或数据表一改，期望值对不上就当场报错。

> 这四条原本是写在 `prompts/judge-v3.md` 里的**手算表格**，后来发现手算错了三处
> （取错了 `ownershipOverride`、漏了反向型的反感免疫）。
> 于是改成可执行断言：**能用断言表达的东西，就不要用文档表格表达。**

平衡性不靠试玩验证——一局 60 秒只覆盖 1190 个组合里的 15 个。
每次改公式都把全部组合跑一遍，数据见 `prompts/judge-v3.md` 第 5 节。

## 安全

- 仓库里**没有任何密钥**。批量生成脚本与服务端只从环境变量读取，
  生成报告里专门有一行「API 密钥：不在本文件中，也不在任何产物中」。
  `.env.example` 只有变量名和空值，连 `sk-xxx` 这种占位符都不写，免得污染密钥扫描。
- `file://` 双击态下 `apiBase` 为空 = **离线模式**，游戏不会发出任何网络请求；
  http(s) 部署态下会自动指向同源 `/api/judge`。
- `/api/health` 与 `/api/judge` 的错误响应**不含任何配置值**，只报告「配没配」的布尔；
  上游原文（网关地址、402 余额不足的响应体）只进服务端日志。
- 静态文件服务做了路径穿越防护，`..%2f` 编码穿越会被挡成 403（冒烟测试里有断言）。
- `BLAMEFALL_ALLOW_ORIGIN` 可挡住扫公开端点的脚本，但它**不是安全边界**
  （Origin 头可伪造），真正的防线是网关侧配额。
- **请求级凭据覆盖**：玩家自带的 `x-bf-key` / `x-bf-model` 只决定用哪个 key、哪个模型，
  **`base` 恒等于环境变量**（不接受请求级 `base`，杜绝 SSRF）；玩家 Key 只存自己浏览器的
  `localStorage`，服务端不回显、不记日志、不进任何响应体（`keySource` 只报「来源」不报「值」）。

### 在线链路验证到什么程度了

开发机上没有 Node，`vercel dev` 跑不了，而 `file://` 双击永远是离线模式 ——
在线链路本来在本地**根本没法验证**。`scripts/dev-server.ps1` 用 `TcpListener`
手写 HTTP 解决了这件事，于是下面这些都是实测而非推断：

| 验证项 | 结果 |
|---|---|
| 冒烟测试 45 条断言 | ✅ 全绿（含路径穿越 403、密钥不回显、validate 全字段契约、genpot/probe 与请求级凭据） |
| 中文编码链路 | ✅ 手拼 JSON 发真实中文字节，`S=65` 与预期逐字对齐 |
| 自动同源 | ✅ http 下 `apiBase` 自动填成同源，标题页显示「在线裁判」 |
| AI 路径端到端 | ✅ 浏览器实测 423ms 返回，`validate()` 全字段通过，中文无乱码 |
| 超时降级 | ✅ mock 延迟 2000ms > timeout 1850ms，正确 `resolve(null)` 并切兜底引擎 |

**真实网关延迟（2026-09-11 生产实测）**：`gemini-2.5-flash` 经 `openai-next` 网关
min/median/max = **1560 / 1711 / 2207ms**（`/api/health?probe=3`，无错误码）。
原 1350ms 预算连 median 都盖不住，已按 `docs/DEPLOY.md` §4 公式重算为
timeout 1850ms / flightMs 2000ms —— 飞行动画多出的 0.5s 玩家无感知。
